# 实验三：桌面物体自动分类整理仿真系统

本分支为实验三仿真部分的最终稳定版本。系统在 Gazebo Fortress 中使用 RoboMaster 底盘、机械臂、夹爪和车载 RGB 相机，自动识别并分类矿泉水瓶与网球。

最终分支：`linear-sorting-final`

## 一、实验目标

本系统按照实验要求完成以下任务：

1. 建立机械臂、夹爪、RGB 相机、桌面网格和两类物体。
2. 仿真相机发布图像，识别节点发布类别、检测框和置信度。
3. 根据检测框中心确定目标所在网格，并根据类别选择对应放置区域。
4. 调用抓取动作，完成取物、分类放置和返回。
5. 循环处理桌面物体，直至六个物体全部完成或没有可执行目标。
6. 处理空网格、未识别物体、不可达目标和抓取失败等异常。
7. 使用一个 Launch 文件启动场景、相机、识别、机械臂和任务控制节点。

## 二、场景与分类规则

- 桌面设置 `G1` 至 `G7` 七个黑色网格，其中 `G4` 固定为空网格。
- 其余六个网格放置 3 个矿泉水瓶和 3 个网球，物体顺序可随机变化。
- 小车从最左侧开始，沿直线左右横移扫描。
- 网球放入左侧网球区域，矿泉水瓶放入右侧水瓶区域。
- 每类设置 3 个独立放置点，减少已放物体之间的碰撞。
- 任务开始后，类别、抓取网格和放置区域均由程序自动决定。
- 黑色网格仅用于位置标记，不设置碰撞体，不影响底盘运动。

| `digital/actions/vision_common.py` | 图像和检测结果的公共处理 |
| `digital/actions/linear_sorting_core.py` | 网格、扫描顺序、目标选择和任务账本 |

| `digital/actions/linear_arm_kinematics.py` | 机械臂逆运动学和可达性判断 |
| `digital/actions/sorting_identity.py` | 已分拣目标身份管理，避免重复识别 |

## 四、完整任务流程

1. 启动 Gazebo、机器人控制器、相机、YOLO 检测器和任务控制节点。
2. 张开夹爪并将机械臂回到安全姿态。
3. 生成 3 个矿泉水瓶、3 个网球和中间空网格 `G4`。
4. 小车从左向右缓慢扫描，根据检测框中心锁定当前目标。
5. 将检测框中心、相机主点和小车横移位置映射到 `G1` 至 `G7`。
6. 对准目标后伸出机械臂，执行对应类别的抓取动作。
7. 试抬目标并验证是否夹取成功。失败时不增加计数，安全回位后重试。
8. 夹取成功后收缩机械臂，使目标避开尚未分拣的物体。
9. 网球运送到左侧区域，矿泉水瓶运送到右侧区域。
10. 放置后验证目标已经落地，再将该目标标记为已完成并增加计数。
11. 小车返回下一个扫描位置；漏检目标在返程或下一趟扫描时重新处理。
12. 六个目标全部完成后正常退出。连续两趟没有可执行目标时，记录原因并结束任务。

物体类别只由图像检测结果确定。Gazebo 位姿仅用于目标身份关联、精确停车、抓取验证和完成计数，不作为类别答案。

## 五、检测框与网格映射

系统使用检测框中心进行网格判断：

1. 计算检测框中心横坐标。
2. 根据相机主点计算目标相对画面中心的偏移。
3. 结合小车当前横移位置和标定比例，得到目标的横向位置。
4. 将横向位置映射到最近的固定网格 `G1` 至 `G7`。
5. 在日志中记录映射来源、网格编号、检测框中心和置信度。

典型日志如下：

```text
GRID MAPPING | source=bbox_center | cell=G3
EMPTY GRID | cell=G4 | handled=skip
```

通过 `G4` 时，小车记录空网格并继续扫描，不执行抓取。

## 六、抓取与安全放置

### 1. 网球

- 保留稳定版本的两阶段闭爪动作：指尖先收，主夹爪后合拢。
- 试抬后验证网球是否随夹爪上升。
- 网球保持球形外观，并使用平底碰撞体减少释放后的滚动。

### 2. 矿泉水瓶

- 使用独立的抓取高度和伸臂距离，避免从瓶身过高位置夹取。
- 试抬成功后先收缩机械臂，再横移运输，避免碰撞后续目标。
- 在水瓶区域前方 `0.080 m` 处完成释放，保留底盘回程通道。
- 放下水瓶后先竖直抬起夹爪，再完全收回机械臂。
- 底盘以 `0.28 m/s` 低速离开放置点前 `0.24 m`，随后恢复正常回程速度。
- 只有确认夹爪、水瓶和底盘通道均安全后，才允许回程。

典型安全日志如下：

```text
BOTTLE DROP STANDOFF | forward=0.080 m | base corridor clear
BOTTLE DROP CLEAR | gripper fully retracted
BOTTLE BASE CLEARANCE | speed=0.28 m/s
```

## 七、异常处理

| 异常 | 处理方法 |
| --- | --- |
| 空网格 | 记录 `EMPTY GRID`，跳过该网格并继续扫描 |
| 暂时未识别 | 降速观察，在返程或下一趟重新检测 |
| 抓取失败 | 不增加计数，张开夹爪、收回机械臂并重试 |
| 目标不可达 | 记录不可达原因，安全回位并在后续扫描处理 |
| 搬运中滑落 | 立即停止当前搬运，不把目标记为完成 |
| 检测流中断 | 停止任务并保存已有日志 |
| 横移无进展 | 停止底盘，报告控制器或桥接异常 |
| 无可执行目标 | 连续两趟没有新增成功目标后安全结束 |

系统只有在放置验证成功后才增加完成计数，不会用尝试次数代替成功次数。

## 八、运行方法

### 1. 下载最终分支

```bash
git clone --branch linear-sorting-final --single-branch \
  https://github.com/lyc-0428/robo_ex3.git robo_ex3_final
```

### 2. 启动完整仿真

在 Jetson 终端执行：

```bash
cd "$HOME/robo_ex3_final/digital"
chmod +x run_linear_sorting.sh
bash run_linear_sorting.sh
```

如需指定场景随机种子，例如 `21`：

```bash
bash run_linear_sorting.sh 21
```

Gazebo、相机画面、YOLO 识别和任务控制由 `digital/launch/linear_sorting.launch.py` 一次启动。运行中按 `Ctrl+C` 可以安全停止。

## 九、最终参数

| 参数 | 当前值 |
| --- | ---: |
| 扫描速度 | `0.060 m/s` |
| 载物运输速度 | `0.65 m/s` |
| 空车回程速度 | `0.95 m/s` |
| 横移加速度 | `1.00 m/s²` |
| 水瓶检测阈值 | `0.40` |
| 网球检测阈值 | `0.50` |
| 水瓶放置前向距离 | `0.080 m` |
| 水瓶离区安全速度 | `0.28 m/s` |
| 水瓶离区安全距离 | `0.24 m` |

为保证成功率，网球两阶段闭爪参数、水瓶抓取姿态和机械臂安全收缩动作保持稳定版本设置。

## 十、日志文件

日志保存在 `digital/logs/`：

| 文件 | 内容 |
| --- | --- |
| `detections.jsonl` | 每帧类别、检测框、置信度和目标状态 |
| `continuous_grasp_*.log` | 网格映射、抓取、放置、异常和任务状态 |
| `linear_exit_code.txt` | 任务退出码 |

关键状态包括：

- `LINEAR TARGET LOCK`：锁定检测目标。
- `GRID MAPPING`：检测框中心映射到固定网格。
- `GRASP FAILED`：抓取验证失败，不计数。
- `EXCEPTION`：异常类型、原因和处理结果。
- `SORTED`：放置验证成功并增加计数。
- `LINEAR SORTING COMPLETE`：六个目标全部完成。
